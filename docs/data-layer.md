# Data layer, session and realtime (dashboard foundation for going live)

Everything the screens need to talk to the backend, without touching the pixel-parity of the fixture-mode screens.
The default and parity builds contain none of the session or API code paths; only `pnpm build:live` does.

```
src/lib/        pure helpers (money, time, colour, dates, business tz, server clock, url, ids)  + differential tests
src/data/       http client, command(), ports (fixture and live), query store, SSE client, theme, toast bus, gen:api
src/auth/       session (GET /me), permissions, cheap middleware logic, live chrome store, validation
src/components/auth/   login-family pages, boot splash, failure card, locked-screen card (docs/auth-ui.md)
scripts/fake-api.ts    stand-in backend for the identity endpoints and /events
tools/dc-compile + design-patches/live   the live variant of the compiler
```

## Build flavours

|                                                          | default (`pnpm build`)                 | parity (`pnpm build:parity`)                      | live (`pnpm build:live`)                                    |
| -------------------------------------------------------- | -------------------------------------- | ------------------------------------------------- | ----------------------------------------------------------- |
| screens                                                  | fixture classes, prod template         | same, `data-dc-tpl` stamped, `__oasisParity` hook | live template patches + bridge on the original classes      |
| `NEXT_PUBLIC_VARIANT`                                    | `''`                                   | `''`                                              | `live`                                                      |
| `_app` providers, session gate, SSE, middleware redirect | none                                   | none                                              | yes                                                         |
| compiler output dir                                      | `src/generated`                        | `.generated-parity`                               | `.generated-live`                                           |
| distDir                                                  | `.next`                                | `.next-parity`                                    | `.next-live`                                                |
| `/api/*`                                                 | not proxied unless `API_ORIGIN` is set | same                                              | rewritten to `API_ORIGIN` (default `http://localhost:4000`) |

`next.config.mjs` also rewrites `/reset/:token` and `/reset-password` to `/reset?token=` in every build (the login pages
exist everywhere). In the live variant it disables gzip (it would buffer SSE through the rewrite) and sets
`experimental.proxyTimeout` to an hour. In production the reverse proxy serves `/api` itself and keeps buffering off
(`proxy_buffering off`, `proxy_read_timeout 1h`), as the backend's api-spec section 7 requires; Next rewrites are
only the dev and fake-API path.

Env: `API_ORIGIN` (build time for `next start`, runtime for `next dev`), `OASIS_SESSION_COOKIE_NAME` (extra accepted
cookie name in middleware), `OASIS_BACKEND_PATH` or `OASIS_OPENAPI` (for `gen:api`), `PORT` (`start:live`, default 3200).

## Typed API client (`src/data/http`)

- `schema.d.ts` is generated by `pnpm gen:api` (`src/data/gen-api.ts`, openapi-typescript 7) from
  `$OASIS_OPENAPI`, else `$OASIS_BACKEND_PATH/docs/openapi.json` (default `../backend`). `pnpm gen:api:check` fails on drift
  (not part of `pnpm check`, because it needs the sibling checkout). The committed file carries only `/events` and
  `/meta/now` today; **`auth-types.ts` is the hand-written contract for the identity endpoints** (a mirror of the backend
  identity module's response schemas). Swap: when `gen:api` produces `/api/v1/me` etc., replace each interface with
  `paths['/api/v1/me']['get']['responses'][200]['content']['application/json']` (the names stay, so no call site changes).
- `ApiClient` (`client.ts`): same-origin cookies; paths are relative to `/api/v1`. On a mutation by a signed-in caller it sends
  `X-CSRF-Token` (from `/me`, login, or `GET /auth/csrf`) and an `Idempotency-Key`. **The key is generated when the action
  starts and reused by every retry of that action**: the client retries network failures, 502/503/504, `IDEMPOTENCY_IN_FLIGHT`
  and `CONCURRENT_UPDATE` (2 retries, 250 ms doubling, `Retry-After` honoured, capped at 10 s) with the same key, so a
  retried refund cannot apply twice. A caller that owns a longer-lived action (a sheet) passes its own key (`Action`).
  Public endpoints (login, invite, forgot, reset) send neither header and treat a 401 as an answer, not a sign-out.
  A 403 `CSRF_INVALID` fetches a fresh token once and replays the request with the same key.
- Errors are RFC 9457 `ApiError` (`problem.ts`): `status`, `code`, `title`, `detail`, `errors[]` (`fieldError('email')`),
  `requestId`, `meta` (`required` on a 403, `currentVersion` on a 412), `retryAfterMs`, `kind` (`http | network | aborted | parse`).
  Non-JSON, empty or malformed bodies fall back to a status-based title; nothing from an untrusted body is trusted by type.

| Status             | Behaviour                                                                                                               |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| 401                | `onUnauthorized` once, then `/login?next=<path>&expired=1` (validated same-origin `next`); no toast                     |
| 403 `FORBIDDEN`    | toast "Your role can't <verb>", the verb from `meta.required` (27 keys), else the command's `denyLabel`, else "do that" |
| 403 `CSRF_INVALID` | refresh the token, replay once                                                                                          |
| 409, 412           | `command()` rolls back, **refetches the command's key and `invalidate` keys**, and shows the server's title and detail  |
| 422                | server message; forms put `errors[]` under the field                                                                    |
| 429                | message with the wait (`Retry-After`); login shows "Try again in N s."                                                  |
| network, 5xx       | "Connection lost" / the server title with a neutral second line; internals are never shown                              |

## command() (`command.ts`)

```ts
const r = await command({
  key: qk.payments('invoice', id), // refetched on success and on 409/412
  idempotencyKey: action.key, // optional: a sheet's Action; generated otherwise
  request: (idem) => port.payments.refund(id, input, { idempotencyKey: idem }),
  optimistic: { queryKey, apply: (cur) => next }, // omit for money actions
  invalidate: [qk.payments('summary')],
  onOk: (inv) => ({ title: 'Refund approved', desc: '...' }),
  denyLabel: 'approve $12.00',
  queryClient: getQueryClient(),
})
```

Optimistic patches are applied after `cancelQueries`, rolled back in reverse order on failure, and skipped when nothing is
cached. **Not optimistic, by design: every money action** (refund, adjust, credit, collect, apply, approve, deny):
the sheet's submit uses its existing disabled style while the request is in flight, and totals change only from the
response. Optimistic is for checklist toggles, add-on toggle, pay and pickup chips, advance and assign-bay (status only),
theme and Settings toggles. A second `command()` with the same key while one is in flight joins it (double click).
Toasts go through `toasts` (`toast.ts`); in the live variant the bridge shows them via the screen's own `flash()`. A toast
raised while no screen is listening yet (the stream failing right after the session loads, before the lazily loaded screen
mounts) is held for 4 s (at most 3) and shown to the first screen that subscribes.

## Data ports (`src/data/ports`)

`DataPort` has one interface per screen region: `catalog`, `hours` (+closures), `emergency`, `calendar`, `availability`, `ops`,
`messages`, `payments`, `people`. Reads are promises; mutations take `{ idempotencyKey }`. `createLiveDataPort(api)` wires
every method to its endpoint (backend design section 5; the live test pins every URL, verb and body).
`createFixtureDataPort()` serves what is static in the designs from `fixtures.ts` (packages, add-ons, tasks, hours,
closures, the eight New Appointment slots, procedural calendar counts); `fixtures.diff.test.ts` runs the ORIGINAL
Operations/Settings classes and fails when a constant drifts (the class strips `/inspection/i` tasks, so does the
fixture). Regions the verbatim classes still own throw `PortUnavailableError` rather than inventing numbers.
`getDataPort()` returns the fixture port outside the live variant and the live port inside it. DTOs in `ports/types.ts`
are provisional: replace each with the generated type when the vertical's paths land.

## QueryStore: reading from a class (`query-store.ts`)

`renderVals()` is synchronous, so a class cannot await a query. `new QueryStore(getQueryClient())` gives it:
`read(key, fetcher)` returns the cached value now and starts the fetch when it is missing or stale (TanStack shares the
in-flight request; after a failure it waits `errorRetryMs`, default 10 s, instead of retrying every render),
`status(key)` / `error(key)` / `refetch(key, fetcher)`, and `subscribe(fn)` which tells the screen once per animation frame
(batched, never per query event; the parity build passes a synchronous `schedule`). Query keys start with the realtime
channel (`ops`, `payments`, `messages`, `settings`, `notifications`) or `me` (`qk` in `query.ts`), which is what makes
SSE invalidation work.

## Realtime (`src/data/realtime`)

`RealtimeClient` is the SSE client for `GET /api/v1/events` on a native `EventSource` (the server's frames: unnamed
`{channel,type,payload,at}` with `id:`, named `ready` and `resync`, `: hb` comments, `retry: 3000`).

- **Resume:** it tracks the last id and reconnects with `?lastEventId=<n>` (the backend accepts the query form because
  `EventSource` cannot set the header by hand).
- **Reconnect:** every error closes the source, marks the stream `down` and retries with exponential backoff
  (1 s, doubling, cap 30 s) and 50-100% jitter; a successful open resets it. After a gap it calls `onResync('reconnected')`
  (refetch everything: replay is best effort); a `resync` frame does the same and moves the cursor to `latestId`.
- **Poll fallback:** while `down`, `onPoll` fires every 20 s (the provider refetches the active queries) and a single
  "Connection lost · retrying" toast is shown.
- **Watchdog:** browsers never show SSE comment lines, so a `: hb` heartbeat is invisible to `EventSource`. Any frame
  counts as life; after 3 heartbeats of silence (60 s; `ready.heartbeatMs` x 3 if larger) the stream is closed and reopened
  with the cursor, without a fallback or a toast. A quiet but healthy stream therefore reconnects about once a minute
  (one request, nothing replayed). **Recommendation for the backend:** also send a visible named `heartbeat` event
  (the client already resets on it) and the churn disappears. The watchdog is also what recovers a stream that dies
  silently: through the `next start` rewrite, an upstream that is destroyed leaves the browser's connection open without
  an `error` (observed with the fake API: `/__fake/drop-streams`), and the client came back after 60 s with
  `?lastEventId=` (nginx closes the downstream properly, so production sees an immediate `error` and the 1 s backoff).
- **Auth:** two failures in a row before the stream ever opens trigger `onSuspectAuth`, which refetches `/me`; its 401
  sends the person to `/login`. An `auth.expired` event does the same. `reconnectNow()` runs on tab visibility and
  `online` events.
- **Invalidation:** `keysForEvent` maps an event to query families and `InvalidationCoalescer` turns a burst into one
  `invalidateQueries` per family per 250 ms window. `rbac.changed` refetches `['me']` and `['settings']`. Events are
  hints (payloads are ids and a version); the stale-version rule of the design is moot because every event is a refetch.

## Server clock and business time (`src/lib`)

`serverNow()` = client clock + (server time - client time at load), the only wall-clock read in the new code
(`clock.ts`; `src/lib/no-bare-time.test.ts` fails on a bare `Date.now()`, `new Date()` or `Math.random()` anywhere else
in `src/lib`, `src/data`, `src/auth`, `src/components/auth`). `tz.ts` is Intl-based and takes the instant as an argument:
`businessToday`, `businessClock` ("10:36 AM", replaces `nowClock()`), `businessStamp` ("Today 10:36 AM", replaces `nowT()`),
`businessMinutes`, `zonedInstant`, `addDays`, `diffDays`, `dateHeading`. Tests cover both DST edges and a device clock a
day off. TanStack stamps `dataUpdatedAt` with the client clock; nothing here compares that with `serverNow()`.

## Pure helpers and their proof (`src/lib`)

`money.ts` (`moneyWhole`, `moneyCents` and `moneyWhole0` with U+2212, `r2`, plus integer-cents `formatCents`,
`formatCentsCompact`, `taxCents` half-up), `time.ts` (`parseT`, `fmtT`, `fmtTRaw`, `clockLabel`, `todayStamp`), `color.ts`
(`hexA`, `lighten`, `statusMeta`, `invoicePill`, employee status), `dates.ts` (`dateFor`, `iso`, `offFor`, `calLabel`,
`fmtDateOffset`, `dayInfo`), `calendar.ts` (`rng`, `dayCount`). `helpers.diff.test.ts` loads the original classes with the
screens' own loader and compares outputs on thousands of inputs (floats, negatives, -0, NaN, half-cent boundaries, every
minute of the day, 1,200 day offsets across year ends, edited hours and closures). Two deliberate differences, both tested:
`statusMeta`/`invoicePill` do not return inherited `Object.prototype` members for keys like `constructor` (the original
returns a function), and `parseT` throws the same `TypeError` as the original on text that is not a time. The logic classes
are **not** switched over to these yet.

## Theme

The per-user server preference is the source of truth (`PUT /me/preferences`). `localStorage['oasis-theme']` is only the
pre-hydration cache: `_app` renders an inline script in `<head>` (live variant) that sets `<html data-theme>` before first
paint; the session load overwrites the cache with the server value before any screen mounts; the cache is cleared on
sign-out. A toggle inside a screen is optimistic (the class flips, the bridge reports it) then saved; a failed save
restores the previous theme and says so. Response headers and the CSP are set in `next.config.mjs` (`headers()`): every
page gets `X-Frame-Options: DENY`, nosniff, `Referrer-Policy: no-referrer`, COOP and HSTS; the live variant in production also
gets the CSP (`script-src 'self'` plus the sha256 of that inline script, no `unsafe-eval`, `connect-src 'self'` for the API and
SSE plus `*.amazonaws.com` for presigned photo URLs, `frame-ancestors 'none'`). The hash in `next.config.mjs` must be the sha256
of `THEME_BOOT_SCRIPT`: `tests/security/headers.test.ts` fails with the new value when the script changes. The live bundles contain
no `eval` or `new Function` (only the fixture and parity builds evaluate the original logic with `loadLogic`), so they need no
`unsafe-eval`; `style-src` keeps `'unsafe-inline'` because the designs style by attribute. `scripts/e2e-security.ts` is the browser
check (headers, framing, CSP violations, hostile names, storage, open redirect, session end).

## The live variant (`--variant=live`)

`tools/dc-compile` gained a third variant. `loadPatchConfig(root, screen, 'live')` appends
`design-patches/live/<screen>.patch.json` to the base ops; prod and parity never read that directory (a test pins it).
New ops, all with guards that fail the build with exit 3 when the template changed:

| Op                                                              | Meaning                                                                   |
| --------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `insert-after`, `insert-before`                                 | splice parsed markup next to the target (`html` or `htmlFile`)            |
| `wrap`                                                          | wrap the target in markup that contains exactly one `<sc-slot></sc-slot>` |
| `replace-text`, `set-attr`, `wrap-if`, `rewrite-href`, `remove` | existing ops, unchanged                                                   |

Markup may live in `design-patches/live/partials/*.html` and `@include(other.html)` another partial (recursion and
path-like names are rejected; partial content is part of the output's patch sha). Synthetic nodes have `tpl: -1` (no
`data-dc-tpl`) and may use `{{= path }}` raw interpolation, which the original templates may not. The live output also
appends the **bridge** (`live-bridge.ts`) to each logic source: `renderVals()` gains `live` from `window.__oasisLive`
(`src/auth/chrome.ts`), the screen subscribes to that store between mount and unmount, `toggleTheme` reports the new
theme, and API toasts reach the screen's `flash()` (arity decides `flash(title, desc)` or `flash(text)`). The build fails
if the class loses `renderVals`, `toggleTheme`, `theme:s.theme` or `flash(`. Tests: patch-op goldens and guard failures,
partial resolution, prod/live isolation, deterministic output, a render of each live screen with real session values
(menu closed and open, view-as bar, Preview-as only for `canViewAs`), and the bridge against the original classes.
`ScreenMeta.variant` in `src/dc/types.ts` is `'prod' | 'parity'`; the live output says `"live"` (not type-checked against it,
because `@generated` resolves to `src/generated` for `tsc`): widen that union when `src/dc` is next touched.

## Migration recipe: converting a screen's logic class to the live data

Prerequisites already in place: session, `can`/`limit`, `getDataPort()`, `command()`, `QueryStore`, `serverNow`, SSE
invalidation by query-key family, theme persistence, toasts, the fake API. For a screen (do Settings first, then Payments, then Operations):

1. **Write the provenance table** before any code (review B13): for every root and list in
   `src/generated/<screen>.bindings.json`, say whether it is _server-supplied_ (a field of a port DTO), _client-derived_
   (pure function of state and data) or _UI state_. Server-supplied values replace the client computation; any difference
   from the oracle goes on the parity allow-list with a reason (`parity/allowlist.json`). Keep the table in `docs/provenance/<screen>.md`.
2. **Copy the class**: `design/extracted/<screen>/logic.original.js` becomes `src/screens/<screen>/Logic.ts`, a TS
   view model extending `DCLogic` (use `declare` for redeclared `props`/`state`/`__host`; keep field order, a vitest ordering test
   guards it). Keep `renderVals()`, the gesture engine, the key handler and the imperative style code verbatim. Do not edit
   `design/`. In the live variant `Screen.tsx` must use the converted class instead of `loadLogic(logicSource)` and the bridge is
   not applied to it, so the class calls the chrome itself: merge `liveChrome.vals()` into `renderVals()` under `live`, subscribe
   with `liveChrome.subscribe` in `componentDidMount`, and call `liveChrome.themeChanged(next, prev)` from `toggleTheme`.
3. **Replace fixtures with reads** (table in `docs/reference/design/dashboard.md` 3.3, port region in parentheses):
   `SERVICES`/`ADDONS`/`ADDON_TASKS` (`catalog.services`), `DEF_HOURS`/`DEF_CLOSURES` (`hours.hours`, `hours.closures`), `oasis-emergency`
   (`emergency.current`), calendar counts (`calendar.summary`/`day`), slots (`availability.slots`), the board (`ops.snapshot`),
   the file (`ops.appointment`), payments (`payments.summary`/`invoices`/`invoice`), roles (`people.roles`). In the constructor create
   `this.store = new QueryStore(getQueryClient())`; in `renderVals()` call `this.store.read(qk.settings('hours'), () => port.hours.hours())`
   and map the DTO to the strings the template wants with the `src/lib` helpers; show structure with empty values while it is `undefined`
   (`keepPreviousData` semantics come free from the cache). Subscribe the screen with `this.store.subscribe(() => this.forceUpdate())`
   in `componentDidMount` and unsubscribe in `componentWillUnmount`.
4. **Replace the clock**: `Date.now()`, `new Date()`, `nowClock()`, `nowT()`, `BASE` become `serverNow()` with `businessClock`,
   `businessStamp`, `businessToday` (the session's `businessTz`); elapsed time from the ISO `startedAt`. The tick keeps its 1 s interval.
5. **Replace every mutation** with `command()`: key = the query family it changes, `request: (idem) => port.x.y(..., { idempotencyKey: idem })`.
   Optimistic patch only for the list above; money actions never. Sheets create an `Action` when they open and pass `action.key`;
   call `action.renew()` after success or close. Success text comes from the response, failure text from `toastForError`
   (`denyLabel` for 403s that name no permission). Before calling the API, gate with `can(session, key)` / `withinLimit(session, kind, cents)`
   and show the existing "Your role can't ..." toast instead (permission map: `docs/reference/design/dashboard.md` 4.5).
6. **Realtime comes free** if keys follow `qk` (`qk.ops(...)`, `qk.payments(...)`): SSE events and the poll fallback invalidate
   the family and the store refetches on the next read. Add a `keysForEvent` entry only for a type that should touch a different family.
7. **Remove the locked-screen logic of the class** where `RouteGate` already decides (Payments `locked`), and read `locked`-style
   booleans from `session.permissions`. Replace the Payments role state and `localStorage` roles with `session.viewAs` (the live
   patches already point "Preview as" at `POST /me/view-as`).
8. **Prove it**: keep the original class as the oracle. Feed the converted class a `FixtureDataPort`-like adapter built from the
   fixture data the original shows and assert `renderVals()` equality key by key (differential test, as `helpers.diff.test.ts`);
   `pnpm parity:all` must stay at zero diff in the parity build, which still runs the original class on fixtures.
   Add a live smoke with `pnpm fake-api` for the commands the screen issues.

Open items the recipe depends on: the backend's `/me` has no `serverTime`/`businessTz` yet (the loader falls back to
`/meta/now`), `viewAs.options` carries limits only for refunds in the menu text, and per-section gating inside Settings
(review B20/B25) and `cli.contact` masking (B43) need the corresponding read models.
